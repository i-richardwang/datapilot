# server-core

- **Runtime-neutral invariant**: this package runs under BOTH Bun (standalone `bun run`) and Node (Docker image, see `Dockerfile.server` CMD; bundled via `scripts/build-server-node.ts`). Never call Bun-only APIs (`Bun.file`, `Bun.serve`, `Bun.password`, …) without a runtime guard — prefer the `node:` equivalent, which works under both runtimes in a single code path. Exception: `startWebuiHttpServer` (webui/http-server.ts) is a Bun-only standalone wrapper used by tests; production traffic goes through `createWebuiHandler` + `webui/node-adapter.ts`.
- The Docker server runs under Node specifically so the real `ws` package negotiates permessage-deflate — Bun's ws shim silently ignores `perMessageDeflate`. Don't "simplify" the Docker CMD back to `bun run`.
- **Session hibernation invariant**: `hibernateSession()` (sessions/SessionManager.ts) drops all non-persisted runtime state. Any new agent-held, runtime-only field added to `ManagedSession` must either be persisted or guarded in `isHibernationSafe()`/`isIdleHibernationSafe()` — otherwise the periodic idle sweep (every 5min, >30min idle) silently discards it. Hibernation also clears session-remembered tool approvals.
- The **Pi subprocess** also runs under Node in Docker: `DATAPILOT_PI_NODE_BIN` + `DATAPILOT_PI_INTERCEPTOR` (set in `Dockerfile.server`, read by `resolvePiRuntimeOverrides()` in `sessions/SessionManager.ts`) point the runtime resolver at system Node and the prebuilt `interceptor.cjs`. Without them the non-packaged resolver path preloads the interceptor's TS source, which forces Bun — costing ~2.1s of bundle parse per spawn vs ~535ms under Node with `NODE_COMPILE_CACHE`. A set-but-missing path throws at session creation (no silent fallback).
